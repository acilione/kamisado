Kamisado

Getting started

There are no published releases or public installer downloads yet.
Use a test build supplied by the maintainer, or build from source:
https://github.com/acilione/kamisado#build-and-run-from-source

No Node.js, terminal, or development tools are needed to use the app.
Choose the portable ZIP for your computer. The "Source code" archives
are for developers. Desktop builds run without installation.

Open and play

Windows
  Open Windows-desktop, then Kamisado, then Kamisado.exe.
  If you received a ZIP, choose Extract All first and open Kamisado.exe
  in the extracted folder. Use a Windows folder such as Downloads, not
  the Linux filesystem inside WSL. Keep the other files beside the app.
  Preferences are saved in your Windows user profile.

Linux
  Open Linux-desktop, then Kamisado, then the Kamisado executable.
  If you received a ZIP, extract the whole archive first. If needed,
  allow execution in Properties > Permissions. Keep the other files
  beside the app. No DEB or RPM installation is required.
  The app includes Electron but still needs Linux desktop libraries.
  See the player guide for missing-library troubleshooting.
  Current Windows and Linux builds are for Intel/AMD 64-bit computers.

Mac
  Mac builds are not included in the automated releases yet. You can join
  a LAN game hosted on Windows or Linux through your Mac's browser.

  If a maintainer supplies a Mac ZIP, choose darwin-arm64 for Apple silicon
  or darwin-x64 for an Intel Mac. Find your processor under Apple menu >
  About This Mac. Extract the ZIP, drag Kamisado.app to Applications, and
  open it there. Mac packaging still needs testing, signing, and notarization.

Current builds are unsigned. If your system shows a publisher warning,
check that the download came from the project or a maintainer you trust.
For Mac opening alerts, follow Apple's guidance:
https://support.apple.com/en-us/102445

Playing

Against the computer
  Choose your game options and a difficulty from 1 to 10 on the first
  screen, then press "Play with computer". This works offline.
  Black moves first; choosing White lets the computer open.

On the same network (LAN)
  1. Connect both devices to the same Wi-Fi or Ethernet network.
  2. The host opens "Connection" and chooses "Host a LAN game".
  3. Choose the rules and press "Create Game".
  4. Share the invitation link or let the other player scan its QR code.
  5. The other player opens the link in a browser on a computer, phone,
     or tablet. They do not need to install the app.

  If both players have the app, the guest can use "Join with a link".
  Send the full invitation, including its address and /game/ part.
  LAN play works without an account or an Internet connection.

Over the Internet (P2P)
  1. The host sets the game options and presses "Create game".
  2. Press "Share link" and send the invitation privately. Phones open the
     system share sheet; desktops without system sharing copy the link.
  3. The guest opens the kamisado://join/... link. The app joins automatically.

  Both apps must be updated for Quick connect. There is no reply to send
  back. Return to Kamisado after sharing the invitation. Keep both apps open.
  Invitations expire after ten minutes. Share them only with your opponent.

  If your messaging app does not recognize the link, paste it into
  "Join a game" in Kamisado. Open the Windows app once to register app links.
  On Linux, portable ZIP users can paste invitations. No website is needed.

  PeerJS Cloud automatically exchanges the connection details. Neither the
  players nor Kamisado's maintainer need an account or a server. Public STUN
  helps find addresses, then moves travel over an encrypted connection
  between the two apps. The game runs on the host's device. The public
  signaling service sees setup metadata but does not carry moves. An outage
  can prevent a new connection; it does not end an already connected match.

  For manual setup, open "Advanced" and choose "Manual code exchange" on
  both apps. The host creates and sends an invitation code; the guest
  creates and sends back a reply code. The host pastes the reply and presses
  "Connect to friend". Direct connections also work with older app versions.

  For automatic fallback, enter temporary TURN addresses, username, and
  password under "TURN relay settings" on both devices before creating or joining
  an invitation. Quick connect first tries direct P2P, then automatically
  retries through TURN using the same invitation. Leave all fields empty
  for direct play only. No relay service is included. Credentials remain
  on the current screen; they are not saved or sent in invitations.
  Manual code exchange still needs fresh codes for a relay retry.

  To skip direct P2P, select "TURN only (skip P2P)" before sharing or joining.
  Both players still need relay credentials. "Import provider settings"
  accepts the provider's ICE servers JSON and fills all three fields at once.

Board controls

Click a tower and then a highlighted destination. Choose Realistic 2D or
Realistic 3D from the view selector. In 3D, drag to rotate, scroll or pinch
to zoom, and use "Reset view" to restore the camera.

Enable "Symbol mode" in the game options, or use the "Symbols" switch
below the board. Matching characters identify square and tower colors.
View and symbol preferences are saved on your device.

Ending a session

Keep the host app open and the computer awake. Closing it ends its games;
unfinished matches are not saved.

In computer or P2P mode, use Connection > End session to return to the connection
window. In LAN or ngrok mode, use Connection > Stop hosting. A temporary
disconnect allows up to 60 seconds to return; the between-round confirmation
countdown can end the match sooner. For P2P, share a fresh invitation if needed.
Restarting the host app cannot restore a match.

Connection troubleshooting

LAN invitation will not open
  Check that both devices are on the same network and the host is still
  running. On a phone, use Wi-Fi rather than mobile data. Allow Kamisado
  through the host's firewall on a trusted private network when prompted.
  Guest Wi-Fi and some hotspots block communication between devices.

  If a VPN blocks local access, change its local-network setting or
  disconnect it for LAN play. If the host has several network adapters,
  open Connection > Connection details and choose "Use for invitation"
  beside the address shared with your friend. Resend the game's updated link.

P2P connection fails
  Update both apps, use the complete invitation, and keep the host app open.
  After an expired code, create a fresh invitation. If
  Quick connect cannot reach its signaling service, try manual exchange.
  In manual mode, use the matching reply for the latest invitation.

  On Windows, run the Windows executable directly. A Linux app running
  inside WSL can face an extra NAT and firewall layer. Running only the
  server in WSL with a Windows browser is different: the browser makes
  the WebRTC connection from Windows.

  If the direct connection times out, try another network or configure
  TURN relay settings. Manual exchange alone cannot bypass a router or mobile
  carrier that blocks direct connections. An existing private VPN can also
  let both computers use a reachable LAN invitation.

Other Internet connection options
  The optional ngrok connection uses the host's account and relays traffic
  through ngrok. The guest joins in a browser. Choose "Connect with ngrok"
  under "Other Internet connection options" and follow the token setup.
